What is a closure in JavaScript? Give a real-world production use case.

💡 Spoken Model Answer:

A closure is the combination of a function bundled together with references to its surrounding lexical environment. In JavaScript, closures allow an inner function to access variables from an outer enclosing function even after the outer function has finished executing.

// Real-World Use Case: Function memoization / Private State
function createRateLimiter(limit) {
  let requestCount = 0; // Private state protected from outside modification
  return function() {
    if (requestCount >= limit) {
      throw new Error("Rate limit exceeded. Try again later.");
    }
    requestCount++;
    return `Request approved (${requestCount}/${limit})`;
  };
}

const limiter = createRateLimiter(3);
limiter(); // "Request approved (1/3)"
limiter(); // "Request approved (2/3)"

⚡ JavaScript Core Question 2 of 80

Explain the difference between var, let, and const, including hoisting and the Temporal Dead Zone (TDZ).

💡 Spoken Model Answer:

var is function-scoped and hoisted with an initial value of undefined. let and const are block-scoped ({ ... }) and are hoisted to the top of their block, but remain uninitialized in the 'Temporal Dead Zone' (TDZ) until execution reaches their declaration line. Accessing them in the TDZ throws a ReferenceError. Additionally, const cannot be reassigned (though objects declared with const remain mutable).

console.log(a); // undefined (hoisted with default value)
var a = 10;

// console.log(b); // ReferenceError: Cannot access 'b' before initialization (TDZ)
let b = 20;

const user = { name: "Govind" };
user.name = "Rahul"; // Allowed: Object mutation
// user = {};        // TypeError: Assignment to constant variable
⚠️ Interviewer Trap: Remember that let and const ARE hoisted! Many freshers incorrectly say 'let and const are not hoisted'. They are hoisted, but access before declaration is blocked by the TDZ.

⚡ JavaScript Core Question 3 of 80

How does the JavaScript Event Loop work? Explain Microtasks vs Macrotasks with a code example.

💡 Spoken Model Answer:

JavaScript is single-threaded with a non-blocking concurrency model powered by the Event Loop. When synchronous code runs on the Call Stack, asynchronous tasks are delegated to Web APIs. Upon completion, their callbacks enter queues: 1) Microtask Queue (Promises, queueMicrotask, MutationObserver) and 2) Macrotask/Task Queue (setTimeout, setInterval, I/O, UI events). The Event Loop executes all available Microtasks completely before processing the next single Macrotask.

console.log("1: Start");

setTimeout(() => {
  console.log("4: setTimeout (Macrotask)");
}, 0);

Promise.resolve().then(() => {
  console.log("3: Promise (Microtask)");
});

console.log("2: End");

// Output Order:
// 1: Start
// 2: End
// 3: Promise (Microtask)
// 4: setTimeout (Macrotask)
⚠️ Interviewer Trap: Interviewers frequently ask what logs first between setTimeout(fn, 0) and Promise.resolve().then(fn). Microtasks ALWAYS drain before the next macrotask runs.

⚡ JavaScript Core Question 4 of 80

Implement debounce and throttle from scratch. When would you use each in a real project?

💡 Spoken Model Answer:

Debounce delays invoking a function until a specified idle time has elapsed since the last time it was called (e.g. search autocomplete or window resize). Throttle guarantees that the function executes at most once per specified time interval (e.g. scroll tracking or game loop physics).

// Debounce: Reset timer on every trigger
function debounce(fn, delay) {
  let timerId;
  return function(...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn.apply(this, args), delay);
  };
}

// Throttle: Enforce execution interval
function throttle(fn, interval) {
  let lastTime = 0;
  return function(...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}
⚠️ Interviewer Trap: Ensure you preserve 'this' and pass '...args' using fn.apply(this, args). If you use a plain arrow function inside without arguments, you lose method context.

⚡ JavaScript Core Question 5 of 80

Compare map(), filter(), reduce(), and forEach(). Which ones mutate the original array?

💡 Spoken Model Answer:

forEach executes a callback for each element and returns undefined; it is used for side effects. map transforms each element and returns a new array of identical length. filter returns a new array containing only elements satisfying a boolean predicate. reduce iterates through the array and accumulates items into a single return value (number, object, array). None of these methods mutate the original array by themselves, though callbacks can inadvertently mutate nested reference types.

const numbers = [1, 2, 3, 4, 5];

const doubled = numbers.map(n => n * 2);      // [2, 4, 6, 8, 10]
const evens = numbers.filter(n => n % 2 === 0); // [2, 4]
const sum = numbers.reduce((acc, curr) => acc + curr, 0); // 15
⚠️ Interviewer Trap: Do not use map() if you aren't using the returned array — use forEach() or for...of instead to avoid unnecessary memory allocation.

⚡ JavaScript Core Question 6 of 80

How does the 'this' keyword behave in arrow functions compared to regular functions?

💡 Spoken Model Answer:

In regular functions, 'this' is dynamically determined by how the function is invoked (as an object method, standalone function, constructor with 'new', or explicitly bound with call/apply/bind). In arrow functions, 'this' is lexically inherited from the enclosing outer scope at the time the function is defined; arrow functions do not have their own 'this', 'arguments', or 'super'.

const profile = {
  name: "Govind",
  greetRegular: function() {
    setTimeout(function() {
      console.log("Regular:", this.name); // undefined (points to window/global)
    }, 100);
  },
  greetArrow: function() {
    setTimeout(() => {
      console.log("Arrow:", this.name);   // "Govind" (lexically inherits from greetArrow)
    }, 100);
  }
};
⚠️ Interviewer Trap: Never use an arrow function as an object method if you need 'this' to reference that object (e.g., const obj = { getVal: () => this.x } fails because this references the global scope).

⚡ JavaScript Core Question 7 of 80

What is the difference between a shallow copy and a deep copy? How do you create both in modern JavaScript?

💡 Spoken Model Answer:

A shallow copy duplicates only top-level primitive values; nested objects or arrays are copied by memory reference, so changing nested data in the clone affects the original. A deep copy recursively copies every nested level, creating a completely independent data structure. Modern browsers support structuredClone() for deep copies.

const original = { user: { name: "Dev" }, role: "Admin" };

// Shallow copy (spread operator)
const shallow = { ...original };
shallow.user.name = "Hacked";
console.log(original.user.name); // "Hacked" (shared reference!)

// Deep copy (modern built-in API)
const deep = structuredClone(original);
deep.user.name = "Secure";
console.log(original.user.name); // Still "Hacked" (isolated!)
⚠️ Interviewer Trap: Avoid JSON.parse(JSON.stringify(obj)) in interviews as your only answer — explain that it drops Functions, Symbols, undefined, and crashes on circular references.

Explain Event Bubbling, Event Capturing, and Event Delegation.

💡 Spoken Model Answer:

When an event occurs in the DOM, it travels through 3 phases: 1) Capturing phase (trickling down from window to the target element), 2) Target phase (the actual element clicked), and 3) Bubbling phase (propagating up from the target back to window). Event Delegation leverages bubbling by attaching a single listener to a common parent element rather than attaching individual listeners to hundreds of child elements, improving memory and handling dynamically created elements.

document.getElementById("todo-list").addEventListener("click", function(e) {
  // Check if the clicked element is a delete button
  if (e.target && e.target.matches("button.delete-btn")) {
    const itemId = e.target.closest("li").dataset.id;
    deleteItem(itemId);
  }
});
⚠️ Interviewer Trap: Understand the difference between e.target (the exact innermost element clicked) and e.currentTarget (the element that owns the event listener, e.g. the parent container).

⚡ JavaScript Core Question 9 of 80

Explain Promises vs async/await. How do you handle parallel asynchronous requests cleanly?

💡 Spoken Model Answer:

Promises represent the eventual completion (or failure) of an asynchronous operation and its resulting value, handling results via .then() and .catch(). async/await is syntactic sugar over Promises that allows asynchronous code to be written in a clean, synchronous-looking style with try/catch error handling. For concurrent requests, Promise.all() runs tasks in parallel (rejecting if any fails), while Promise.allSettled() returns the outcome of all promises regardless of rejections.

async function fetchDashboardData(userId) {
  try {
    // Run independent network requests concurrently!
    const [userRes, postsRes, statsRes] = await Promise.all([
      fetch(`/api/users/${userId}`),
      fetch(`/api/users/${userId}/posts`),
      fetch(`/api/users/${userId}/stats`)
    ]);
    const user = await userRes.json();
    return { user, posts: await postsRes.json() };
  } catch (err) {
    console.error("Dashboard fetch failed:", err);
    throw err;
  }
}
⚠️ Interviewer Trap: Avoid sequential await waterfalls! Don't do: const a = await fetchA(); const b = await fetchB(); if a and b do not depend on each other — use Promise.all().

What is Function Currying? Implement a curried function sum(1)(2)(3).

💡 Spoken Model Answer:

Currying transforms a function that takes multiple arguments into a sequence of nested unary functions that each take a single argument. It facilitates function composition, reuse, and partial application of configuration arguments.

// Fixed-arity curry
function sum(a) {
  return function(b) {
    return function(c) {
      return a + b + c;
    };
  };
}
console.log(sum(1)(2)(3)); // 6

// Generic infinite curry
const add = a => b => b !== undefined ? add(a + b) : a;
console.log(add(1)(2)(3)(4)()); // 10
⚠️ Interviewer Trap: Explain practical use cases: configuring API request headers once and reusing the returned function for specific endpoints.

⚡ JavaScript Core Question 11 of 80

How does prototypal inheritance work in JavaScript? What is the prototype chain?

💡 Spoken Model Answer:

JavaScript does not use classical inheritance; it uses prototypes. Every JavaScript object has an internal [[Prototype]] link (accessible via Object.getPrototypeOf() or __proto__) pointing to another object. When accessing a property on an object, JavaScript searches the object itself; if not found, it traverses up the prototype chain until it finds the property or reaches null (the end of the chain on Object.prototype).

function Developer(name, stack) {
  this.name = name;
  this.stack = stack;
}
// Shared method placed on the prototype to save memory
Developer.prototype.code = function() {
  return `${this.name} is coding in ${this.stack}`;
};

const dev = new Developer("Govind", "MERN");
dev.code(); // "Govind is coding in MERN"
⚠️ Interviewer Trap: Classes introduced in ES6 are syntactic sugar over prototypal inheritance; they do not introduce a new object-oriented inheritance model.

⚡ JavaScript Core Question 13 of 80

Explain strict equality (===) vs loose equality (==) and implicit type coercion.

💡 Spoken Model Answer:

Loose equality (==) performs implicit type coercion (converting types before comparing according to the Abstract Equality Comparison Algorithm), while strict equality (===) checks both value and type without coercion. For example, '0' == 0 is true because string '0' converts to number 0, but '0' === 0 is false.

console.log(0 == false);        // true (coerced)
console.log(0 === false);       // false (number !== boolean)
console.log(null == undefined); // true
console.log(null === undefined);// false
console.log([] == 0);           // true ([] becomes "" then 0)
⚠️ Interviewer Trap: Always recommend === in production code to avoid bizarre bugs caused by implicit coercion.

What are Generator functions and how does the 'yield' keyword work?

💡 Spoken Model Answer:

A generator function (declared with function*) can pause its execution using the 'yield' keyword and resume later when its .next() method is called. Unlike normal functions which run to completion, generators return an Iterator object, enabling custom iterative algorithms and memory-efficient infinite sequences without allocating huge arrays.

function* idGenerator() {
  let id = 1;
  while (true) {
    yield `USER-${id++}`;
  }
}

const gen = idGenerator();
console.log(gen.next().value); // "USER-1"
console.log(gen.next().value); // "USER-2"
⚠️ Interviewer Trap: Generators form the underlying foundation for Redux-Saga and async iterators in Node.js streaming.

What are JavaScript ES Modules vs CommonJS modules? When is each used?

💡 Spoken Model Answer:

CommonJS (CJS) uses require() and module.exports, which are synchronous and evaluated at runtime; it has been the historical standard for Node.js. ES Modules (ESM) use import and export, which are asynchronous and statically analyzable at compile time (enabling tree-shaking). Modern Node.js and browsers support ESM natively.

// CommonJS (Node traditional)
const fs = require('fs');
module.exports = { myFunction };

// ES Module (Modern Standard)
import fs from 'fs';
export const myFunction = () => {};
⚠️ Interviewer Trap: You cannot use import in a CommonJS file without dynamic import() or setting 'type': 'module' in package.json.

How does the Virtual DOM and Reconciliation algorithm work in React?

💡 Spoken Model Answer:

The Virtual DOM is a lightweight JavaScript object representation of the real DOM. When state changes, React creates a new Virtual DOM tree and runs its Reconciliation algorithm (powered by React Fiber) to compare (diff) the new tree with the previous one. It computes the minimum set of DOM mutations needed and batches them to the real DOM, avoiding expensive layout reflows.

// Conceptual representation of a Virtual DOM node
const vdomNode = {
  type: 'button',
  props: {
    className: 'btn-primary',
    onClick: handleClick,
    children: 'Submit Form'
  }
};
⚠️ Interviewer Trap: Don't say 'the Virtual DOM is faster than the real DOM in every scenario'. Directly updating a single DOM node is faster, but React's Virtual DOM provides predictable declarative rendering and eliminates unoptimized manual DOM manipulation at scale.

🔥 React & TypeScript Question 17 of 80

Why does React require a unique 'key' prop in lists? What breaks if you use array indices?

💡 Spoken Model Answer:

React uses keys to identify which items in a list have changed, been added, or been removed during reconciliation. If you use array indices as keys and reorder, prepend, or filter the list, the index of each item changes. React matches items by key and mistakenly reuses the existing DOM nodes and component local state (like input values), causing UI bugs and broken animations.

// ❌ Dangerous: Index keys cause state mismatch on reorder/delete
{items.map((item, index) => <TodoItem key={index} data={item} />)}

// ✅ Correct: Unique persistent ID
{items.map(item => <TodoItem key={item.id} data={item} />)}
⚠️ Interviewer Trap: Explain that using index as key is only safe if: 1) the list is strictly static, 2) items are never reordered or filtered, and 3) items have no local state.

🔥 React & TypeScript Question 18 of 80

Explain useEffect: dependency array rules, cleanup functions, and how to avoid infinite loops.

💡 Spoken Model Answer:

useEffect handles side effects (API calls, subscriptions, DOM mutations). If dependencies are omitted, it runs on every render. If an empty array [] is passed, it runs once on mount. If variables are passed [a, b], it runs when any dependency changes. The returned cleanup function runs before the effect re-runs and on unmount to prevent memory leaks. Infinite loops occur when the effect updates a state variable that is also listed in its own dependency array without a guard.

useEffect(() => {
  const controller = new AbortController();
  
  async function loadData() {
    try {
      const res = await fetch(`/api/profile/${userId}`, { signal: controller.signal });
      setData(await res.json());
    } catch (err) {
      if (err.name !== 'AbortError') setError(err);
    }
  }
  loadData();

  // Cleanup: Cancel pending network requests if user changes page/id
  return () => controller.abort();
}, [userId]);
⚠️ Interviewer Trap: Mention AbortController for cancelling fetch requests in the cleanup function — interviewers love seeing real production practices.

Compare Controlled vs Uncontrolled components in React. When would you use useRef?

💡 Spoken Model Answer:

A controlled component has its form data handled by React state (value={val} and onChange={e => setVal(e.target.value)}), making React the single source of truth. const upload = () => {
  const file = fileInputRef.current?.files?.[0];
};
<input type="file" ref={fileInputRef} />

🔥 React & TypeScript Question 20 of 80

When should you use useMemo and useCallback? What is the performance cost of overusing them?

💡 Spoken Model Answer:

useMemo caches the result of an expensive calculation (e.g. sorting 5,000 items) between renders. useCallback caches a function instance to prevent unnecessary re-renders of memoized child components (React.memo). Overusing them adds memory overhead and dependency array comparison checks that can exceed the cost of simple re-renders. Use them only when profiling demonstrates measurable re-render bottlenecks.

// useMemo: caches expensive computed value
const filteredList = useMemo(() => {
  return largeDataset.filter(item => item.score > threshold);
}, [largeDataset, threshold]);

// useCallback: caches stable function reference for child props
const handleSelect = useCallback((id: string) => {
  dispatch({ type: 'SELECT', id });
}, [dispatch]);
⚠️ Interviewer Trap: Don't wrap primitive variable assignments or cheap inline calculations in useMemo. It signals cargo-cult optimization to a senior interviewer.

In TypeScript, what is the difference between 'interface' and 'type' aliases?

💡 Spoken Model Answer:

Both can define object structures and be extended. Key differences: 1) Declaration merging: multiple interfaces with the same name merge their properties automatically, while types cannot. 2) Types can define union types (type Role = 'admin' | 'user'), primitives, and tuples, which interfaces cannot. Use interface for public component props and object models; use type for unions, tuples, and utility transformations.

// Interface supports declaration merging
interface User { id: string; }
interface User { name: string; } // Merged into { id: string, name: string }

// Type alias supports unions & tuples
type Status = 'idle' | 'loading' | 'success' | 'error';
type Coordinates = [number, number];
⚠️ Interviewer Trap: Never say 'interfaces are for OOP and types are for functional'. Both work in functional React; choose based on features like unions vs declaration merging.

How do you create and type a custom hook in React with TypeScript?

💡 Spoken Model Answer:

A custom hook is a JavaScript function whose name starts with 'use' and that calls other React hooks. In TypeScript, return types should be explicitly typed, often using 'as const' on tuple returns to ensure correct type inference for destructured consumers.

import { useState, useEffect } from 'react';

export function useWindowWidth(): number {
  const [width, setWidth] = useState<number>(() => window.innerWidth);

  useEffect(() => {
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener('resize', handleResize);
    return () => window.removeEventListener('resize', handleResize);
  }, []);

  return width;
}
⚠️ Interviewer Trap: Ensure custom hooks follow the Rules of Hooks (never call hooks inside loops, conditions, or nested functions).

🔥 React & TypeScript Question 25 of 80

What are React Error Boundaries? What kinds of errors can they NOT catch?

💡 Spoken Model Answer:

Error Boundaries are React components that catch JavaScript errors anywhere in their child component tree, log the errors, and display a fallback UI instead of crashing the entire component tree. They MUST be class components using static getDerivedStateFromError() and componentDidCatch(). They cannot catch: 1) Event handler errors, 2) Asynchronous code (setTimeout, fetch), 3) Server-side rendering errors, and 4) Errors thrown inside the boundary component itself.

class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError(error) {
    return { hasError: true };
  }
  componentDidCatch(error, info) {
    logErrorToService(error, info);
  }
  render() {
    if (this.state.hasError) return <h2>Something went wrong.</h2>;
    return this.props.children;
  }
}
⚠️ Interviewer Trap: Explain that for event handler errors, standard try/catch blocks are still required because React does not render during event execution.

How does React 18 Automatic Batching work?

💡 Spoken Model Answer:

Prior to React 18, React only batched state updates inside React event handlers (like onClick). State updates inside promises, setTimeout, or native event listeners triggered separate re-renders for each state setter. In React 18, Automatic Batching groups all state updates into a single re-render regardless of where they originate, significantly improving performance.

// In React 18: Only 1 single re-render happens here!
setTimeout(() => {
  setCount(c => c + 1);
  setFlag(f => !f);
}, 1000);

How do you optimize rendering performance for large lists of 10,000 items in React?

How does bcrypt hash passwords and why are salt rounds critical?

Compare Offset-based vs Cursor-based pagination for large datasets.

  if (cached) return JSON.parse(cached);

  // Cache miss: Query DB & store in Redis with 1-hour expiration (TTL)
  const job = await db.jobs.findById(jobId);
  await redis.setex(`job:${jobId}`, 3600, JSON.stringify(job));
  return job;
}
⚠️ Interviewer Trap: Always specify a Time-To-Live (TTL) on cached keys; otherwise, stale data persists indefinitely and causes cache bloat.

💡 Spoken Model Answer:

A Monolith bundles UI, business logic, and database access into a single unified codebase and deployment artifact. Pros: simple to build, test, debug, and deploy; low initial operational overhead. 💡 Spoken Model Answer:

A message queue enables asynchronous processing by decoupling time-consuming tasks from the client request-response lifecycle. Operations like sending welcome emails, resizing video uploads, or generating PDF invoices shouldn't block the HTTP response. The web server pushes a job payload to the queue and returns an immediate 202 Accepted response; background worker processes process jobs from the queue asynchronously.

What is Docker and containerization? How does a container differ from a Virtual Machine?

💡 Spoken Model Answer:

A container packages an application and all its system dependencies into an isolated runtime unit that runs identically on any machine. A Virtual Machine (VM) virtualizes the underlying hardware and runs an entire Guest Operating System (hundreds of MBs/GBs with slow boot times). A Docker container shares the host machine’s OS kernel, isolating processes at the user space level (lightweight, megabytes in size, and starts in milliseconds).

🏗️ System Design & Web Architecture Question 65 of 80

What is CORS (Cross-Origin Resource Sharing) and what is an HTTP Preflight (OPTIONS) request?

💡 Spoken Model Answer:

CORS is a browser security mechanism that restricts web pages from making HTTP requests to a domain different from the domain that served the web page. For 'non-simple' requests (e.g. requests with Content-Type: application/json or Authorization headers, or methods like PUT/DELETE), the browser automatically sends an HTTP OPTIONS preflight request before the actual request. The server must respond with appropriate Access-Control-Allow-Origin, Methods, and Headers before the browser allows the actual request.

// Preflight Request:
OPTIONS /api/users
Origin: https://myfrontend.com
Access-Control-Request-Method: POST

// Server Response:
Access-Control-Allow-Origin: https://myfrontend.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
⚠️ Interviewer Trap: CORS is strictly a BROWSER security feature! Postman, curl, and server-to-server calls do NOT enforce CORS.
